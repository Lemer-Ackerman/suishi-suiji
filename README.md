# 随时 · 随记

一个聊天式桌面记事窗口。输入、发送，每条内容独立显示。默认置顶，按日期翻阅，在凌晨 4 点为你打开新的一页。

支持 **Windows 10/11 x64** 和 **macOS（Apple Silicon / Intel）**。离线使用，笔记是普通 UTF-8 文本文件，无账号、无上传、无统计。

![随时 · 随记界面](docs/screenshot.png)


## 下载与安装

在 [Releases](https://github.com/Lemer-Ackerman/suishi-suiji/releases) 下载：

- Windows：安装版 `*-setup.exe`，或无需安装的 `*-portable.exe`。
- Apple Silicon Mac（M 系列）：`*-mac-arm64.dmg`。
- Intel Mac：`*-mac-x64.dmg`。

macOS 打开 DMG 后把“随时 · 随记”拖到 Applications；ZIP 是对应架构的备用包。

当前发布包未使用商业开发者证书签名或 Apple 公证，首次打开可能出现系统提示。确认下载自本仓库后，在 macOS 的“系统设置 → 隐私与安全性”允许打开；Windows 可能显示 SmartScreen 提示。正式面向公众推广前应配置代码签名与公证。

## 使用

- **置顶**：启动时默认置顶，右上角「⋯ → 取消窗口置顶」可开关。
- **显示 / 隐藏**：默认 `Shift + 空格`；右上角「⋯ → 设置」可录入自定义组合键。冲突时提示更换，保留原快捷键。退出应用后快捷键不再生效。
- **日历**：右上角「⋯ → 日历」点击日期查看历史记录，也可以继续追加；带圆点的日期已有内容。“回到今天”回到当前记事日。
- **4 点翻页**：采用电脑本地时间。00:00–03:59 属于前一天，04:00 起自动切换到新的日期；休眠后唤醒也会检查。如果新日期已有笔记，会加载原内容，不覆盖。
- **发送即保存**：Enter 发送，Shift + Enter 换行。成功写入磁盘后才显示记录并清空输入框；失败时保留草稿供重试。未发送、空白或只有空格换行时不生成文件。最后一条记录删除后移除对应文件。
- **记录时间**：每条消息显示本地时间，精确到秒（`HH:mm:ss`）；鼠标悬停可见完整日期，文件中保留完整日期与时间。
- **意外退出恢复**：输入时持续保存草稿，不等点击发送或正常退出。看到“草稿已保存”后，即使强制结束进程，重新打开也会恢复输入框内容。草稿按日期单独存放在笔记目录的隐藏子目录 `.drafts` 中，不创建当天的 `.txt`；发送成功后清除草稿。重开时如果当天没有草稿，会恢复最近一份未发送草稿所在日期。日历空心点表示该日有草稿。
- **开机启动**：「⋯ → 设置 → 开机自动启动」可开关，默认关闭。启用后，下次登录电脑时在后台启动，不自动弹出窗口；按快捷键召出。请先把 macOS 应用放进 Applications，或安装 Windows 版本，再开启此选项。便携版需放在固定位置，移动后重新设置。
- **复制 / 编辑 / 删除**：每条记录下方提供三个图标，悬停显示文字提示。点击铅笔编辑，保存后保留原始时间和排序；Enter 换行，Ctrl / ⌘ + Enter 保存，取消放弃修改。编辑草稿自动保存，意外退出后恢复；「⋯」也可操作当天全部记录。删除前弹窗确认。
- **关闭**：「⋯ → 隐藏窗口」隐藏窗口，程序继续在系统托盘 / macOS 菜单栏运行。完全退出请使用设置或托盘中的“退出随时 · 随记”。

编辑中的草稿单独保存在应用设置目录的 `edit-draft.json`，与未发送的新消息草稿互不影响；保存成功或取消后清除。

## 保存位置

- Windows 首次运行默认创建 **`D:\Daynote`**；没有 D 盘或无法写入时，要求选择其他文件夹，不静默改存 C 盘。
- macOS 默认创建 **`~/Documents/Daynote`**（文稿 / Daynote）。
- 在 **设置 → 更换文件夹** 中随时自定义位置。已有笔记会复制到新目录，原目录保留为备份。同名且内容不同的笔记会阻止切换，避免覆盖。
- 笔记文件名如 `2026-11-19.txt`，可以直接用系统记事本或文本编辑器打开。每条记录附带时间和标识，便于聊天展示与单条删除；旧的普通文本文件会作为一条历史记录加载。
- 少量应用设置和系统缓存仍存储于操作系统标准用户目录；Windows 的“不在 C 盘”指笔记正文保存位置。

建议选择本地可写文件夹。网络盘或可拔出的磁盘断开后会显示保存错误，并保留输入框中的未发送文字；请恢复目录或连接后重试发送。草稿恢复以界面显示“草稿已保存”为准，未写入磁盘的最后一次输入和磁盘故障不在恢复保证范围内。备份时请连同 `.drafts` 文件夹一起复制，更换保存文件夹会自动复制草稿。不要在多个程序中同时编辑同一个日期文件：本版本不提供外部修改合并。单日内容上限为 1 MiB。

## 开发

需要 Node.js 24。

```sh
npm ci
npm start
npm run check
npm test
npm run test:e2e
```

```sh
# 在 macOS 构建 Apple Silicon 与 Intel 的 DMG / ZIP
npm run pack:mac
# 在 Windows 构建 x64 安装版与便携版
npm run pack:win
```

GitHub Actions 在 Windows、macOS 各自执行真实桌面集成测试并打包，产物位于 Actions 的 Artifacts。

打包后还会实际启动产物；Windows 会静默安装安装包再验证。检查记录落盘、秒级时间和开机启动开关。macOS 自启动使用当前用户的 `~/Library/LaunchAgents/com.lemer.daynote.plist`；Windows 使用系统登录启动项。关闭开关会移除对应配置。两者只在用户登录后启动，不在未登录状态运行；实际重启登录仍取决于系统是否允许该启动项。

## 设计

使用 Electron 的原生置顶窗口、全局快捷键、托盘和剪贴板能力。界面仅载入本地资源，启用上下文隔离与进程沙箱，禁止网络访问与外部页面导航。主进程校验来自界面的请求，并独占文件写入。

笔记采用“写入临时文件 → 刷新到磁盘 → 替换目标文件”的原子写入方式，避免写一半破坏原文件。4 点边界按本地日历运算，不是固定减去四小时，因此兼容夏令时切换。

草稿使用相同的原子写入，每条草稿拥有固定标识，发送后沿用该标识。重试发送相同标识不会重复追加；若在写入记录后、删除草稿前崩溃，已发送记录优先，旧草稿不会再次恢复。测试包含真实强制结束进程后的恢复，以及模拟提交中断的去重检查。

适合个人单机记事；日期文件按需加载，不把所有笔记正文常驻内存。当前日历启动时扫描文件名，数十年每日一篇也只是数千个文件。云同步、多人协作、超大附件不属于本版本；需要这些能力时应另做同步冲突处理和索引。
